# W1 — Window close state machine

## What changed

- `HostBridge.WebAlive` is set in `OnWebMessage` (every inbound web message). Not keyed on `perf.mark` / `web-ready`, so Release without `FC_PERF_TRACE` still fail-closes.
- Native close timeout/error/detach: if the web has spoken, **fail closed** (clear `_closePromptInFlight`, do not close). If the page never came up, **fail open**.
- `window.close` with `alreadyConfirmed: false` (or omitted) now takes the same ask-the-web path as native chrome close. `alreadyConfirmed: true` still closes immediately.
- `_hostExitInProgress` is cleared when `TakeAllWindows()` is empty, after host-exit teardown, and at the start of `EnsureHostExitHook` (Show registers a new window).
- Tests: `CloseMachineTests.cs` (no WebView2) and `HostBridgeTests` coverage for timeout, Detach, and `WebAlive`. Direct `DisposeWebViewCore()` instead of reflection.

## 0.2 breaking-change bullets

- In-app `window.close` with `alreadyConfirmed: false` no longer closes the HWND unconditionally. The host asks the web via `window.closeRequested` first. Authors/web must keep sending `alreadyConfirmed: true` after a completed discard check (the in-app Exit path already does).

## Boundary notes

- Did not touch `app.svelte.ts` (W4 owns stacked-discard reuse), `FluentConfigSession.cs`, `FluentConfigWindowManager.cs`, or RPC dispatch.
- Test seams live in `Lifecycle.cs` (`BindHostForTests`, `DeliverNativeCloseReplyForTests`, host-exit flag helpers). No `CloseCoordinator`.
- `EnsureHostExitHook` Application subscriptions are not exercised in unit tests (throwaway STA threads vs one WPF Application per AppDomain). Flag reset at the top of that method is.
- `HostExit_EmptyTakeAll_ClearsStickyFlag` calls `TakeAllWindows()`; it shares the same process-wide registry race as existing `FluentConfigWindowManagerTests`.
