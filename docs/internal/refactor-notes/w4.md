# W4 — web store, pills, each-key identity

## What landed

- `{#each}` keys for `RepeatableRowsControl` and `DynamicTextboxesControl` are a plain index. Content fingerprints remounted the row on every keystroke and stole focus. User-locked: do not invent a row id that could leak into persisted data. Removing a middle row still remounts later rows (index identity); that is accepted.
- Deleted the pill selection `$effect`. `selected` is raw user intent; `activeItem` / `activeName` resolve the visible tab. Template highlighting and Remove use `activeName`.
- `patchPillItems` now uses the same recursive walk as `patchDropdownOptions` (groups, pill items / templates, repeatable-rows). Nested `PillInput` inside a Grid / WithVisibility receives host-expanded items after `pill.changed`.
- Per-key dirty tracking: `setValue` / `deleteValue` update one path; `isDirty` is `dirtyKeys.size > 0` with a generation counter for reactivity. Bootstrap and successful save clear the set. `values.patch` still dual-writes `values` and `savedValues`, then rebuilds the dirty set from remaining diffs so leftover user edits stay dirty.
- Stacked discard dialog: reuse the in-flight promise instead of resolving the first with `{ allowClose: false }` and opening a second.
- `dispose()` clears toast, save-message, and progress `setTimeout` handles.
- Extracted `dirtyKeys.ts` and `schemaWalk.ts` (plain `.ts`) so vitest can cover them without a Svelte plugin.
