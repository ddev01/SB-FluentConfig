# I2 — Defer eager dropdown Refresh

## Prerequisites (re-confirmed on this tree)

All three were present; the eager call was removed.

1. **W2** throws on `.DefaultIndex()` for refresh-only dropdowns: `FluentConfig/Host/Builders/PendingControl.cs:213-223` (`RefreshOnlyDropdown_DefaultIndex_Throws` in `BuilderGuardTests.cs:87-95`).
2. **W3** seeds `defaultByValue` in the empty-options branch of `CollectDropdown`: `FluentConfig/Host/Core/SettingsDefaultsCollector.cs:108-121` (`Collector_OptionlessDropdown_SeedsDefaultByValueOnIdKey` in `SettingsIdentityTests.cs:43-67`).
3. **W5** `refreshCache.consumeOnce` still allows the first mount refresh: `FluentConfig/web/src/lib/refreshCache.ts:8-13`, keyed `dropdown:${saveKey}` / `filepath:${saveKey}` at `DropdownControl.svelte:25` and `FilepathControl.svelte:59`.

## What changed

- `BuildDropdown` no longer calls `refreshFn()` when static options are empty. Refresh-only dropdowns ship with null/empty `options`. The callback is still registered for `dropdown.refresh`.
- First paint uses collected defaults (`defaultByValue` on `valueSaveKey` when pair-valued, else `saveKey`). The web’s first-mount `onMount` gate (`refreshable && !options.length` + `consumeOnce`) fetches options after paint.

## Inverted / new tests

- `RefreshOnlyDropdown_SeedsInitialOptions` → `RefreshOnlyDropdown_ShipsEmptyOptions`: refreshable, options empty, author callback **not** invoked at build; still registered and returns three items when invoked.
- `DropdownWithStaticOptions_DoesNotSeedFromRefresh` unchanged.
- New `RefreshOnlyPairDropdown_BehindVisibility_DoesNotEagerRefresh`: pair-value reward picker inside `WithVisibility`; callback count stays 0 at build; `reward_id` seeded, `reward_display` absent. Fails if the host still eagerly `Refresh()`es (options would be filled and the callback would run) or if the empty-options collector seed is missing (`reward_id` absent).
- New vitest `isVisible pair-value empty options uses defaultByValue on first paint`: gated block visible from seeded id / schema `defaultByValue` with `options: []`; `''` still hides.

## Flash risk (no live WebView2)

Could not drive a Streamer.bot WebView2. Closest substitute: emit path + web first-paint path + the tests above.

**Kept the change.** Gated visibility on the pair **id** is stable on first paint without options:

- Host `Collect` runs on the empty-options node and writes `defaultByValue` onto `valueSaveKey` before bootstrap.
- `isVisible` treats that live id as present (`''` remains “explicit none”). With omitted values it still falls back to `defaultByValue` even when `options` is empty (`visibility.ts` `dropdownDriverDefault`, `!pairDisplay` branch).
- First-mount refresh `keep`s an in-list default (`resolveDropdownRefresh`); it does not clear a matching id.

Residual (not gated-block flash; W7 should mention):

- `SelectMenu` `displayLabel` needs an option match, so the trigger can show the placeholder until the first-mount refresh fills options. The visibility group itself does not depend on that.
- If Refresh returns empty (Twitch offline), mount refresh still **clears** an unmatched default — same as the old empty-seed + mount-refresh path, not new to I2.
